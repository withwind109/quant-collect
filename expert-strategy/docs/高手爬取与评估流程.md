# 高手爬取与评估流程报告

> 版本：2026-10-19 · 对应代码：expert-strategy（FastAPI + 原生 HTML）
> 本文说明两条主线：**数据怎么爬进来**（爬取链）与**高手怎么评出分**（评估链），以及两者的衔接方式。

---

## 0. 一页全景

```
┌──────────────────────────── 爬取链 ────────────────────────────┐
│  Web「高手评估」页 / CLI                                        │
│    → POST /api/expert-crawl/run                                │
│    → jobs.start_job("crawl") → scripts/run_job.py 子进程        │
│    → cli.py crawl → src/pipeline.py: run()                     │
│        ① 定交易日（多源投票）                                    │
│        ② 各渠道抓高手榜 → 当日操作明细 → 个股热度榜               │
│        ③ 补「当日活跃高手」→ 排序/聚合                           │
│        ④ 落盘 data/crawl/<日期>/ + 写 SQLite（幂等）              │
└────────────────────────────────────────────────────────────────┘
                              ↓ 每日增量
┌──────────────────────────── 评估链 ────────────────────────────┐
│  Web「运行评估」                                                │
│    → POST /api/expert-crawl/evaluation/run                     │
│    → jobs.start_job("expert_eval") → cli.py expert-eval         │
│    → src/strategy/expert_eval.py: evaluate()                   │
│        ① load_expert_signals：crawl_trade ∪ history_bulk 去重   │
│        ② _kline_for：补行情（东财→腾讯兜底）→ 本地 K 线索引       │
│        ③ simulate_expert：逐高手镜像回测（等同无脑跟单）          │
│        ④ compute_metrics：全套盈利指标                          │
│        ⑤ _assign_scores：分位秩综合评分 → 排序                   │
│        ⑥ 写 data/eval/latest.json（Web 页直接读）                │
└────────────────────────────────────────────────────────────────┘
```

**两条链的衔接点**：爬取链每天往 `crawl_trade` 表追加流水；评估链把流水（+批量回补全史）当信号回放。**只爬一两天时每人约 1 笔信号，算不出指标——先跑 bulk-history 回补，评估才有意义。**

## 1. 爬取链：数据怎么进来

### 1.1 入口与任务化

| 触发方式 | 链路 |
|---|---|
| Web 页面（分渠道卡片） | `POST /run` → `web/jobs.py: start_job("crawl")` → `scripts/run_job.py` 子进程 → `cli.py crawl` → `pipeline.run` |
| CLI | `python main.py crawl --sources eastmoney --top 50` |

后台任务统一由 `run_job.py` 驱动：子进程逐行实时写 `logs/job_crawl.log`，状态落状态文件，前端轮询 `/status` + `/log`。

### 1.2 单次采集的五步（`pipeline.run`）

1. **定交易日**（`resolve_trade_date`）：各源探测候选日期后投票——源数量优先 → 当日活跃量 → 日期新旧。避免雪球非交易日调仓把全网数据过滤空。
2. **抓高手榜**（`hot_experts`）：东财走 `emdcspzhapi.dfcfs.cn/rtV1` 实盘榜；雪球/同花顺/支付宝各有其榜。
3. **抓当日操作明细**（`trades`）——东财有两条流水，是理解全系统的关键：
   - **模拟盘流水**（`simqry2.eastmoney.com/qry_tzzh_v2`，`type=spo_superior_detail`）：匿名接口 + Cookie 认证，逐页倒序扫描全站操作流水，筛出目标日。落到 `market_type='sim'`。
   - **实盘流水**（`spzhapi.dfcfs.cn/rtV3`，SM4 签名信封）：**只对本账户关注的组合开放**，所以只查关注列表（config 的 `spzh_follow` ∪ Web 关注列表）。落到 `market_type='live'`。
4. **补当日活跃高手 + 排序聚合**：操作明细里不在榜上的组合也会进榜（收益率取自明细自身）；高手榜按累计收益率降序，买入按「高手收益率 → 金额」降序；按个股聚合买入热度。
5. **双写**：落盘 `data/crawl/<日期>/*.json|csv`；SQLite 入库（`crawl_expert` / `crawl_trade` 等，按日期幂等可重跑）。

### 1.3 抓取后端（反爬设计）

- **默认无头浏览器**（`core/browser.py` `BrowserClient`）：预热东财主站拿真实会话 → 同源 `fetch` 发请求 → Page 按域缓存常驻 → 剔除浏览器禁设的 header → stealth 抹除 webdriver 特征。拟人化，封禁概率低。
- **失败回退** `curl_cffi` 轻量 HTTP；**批量回补强制走轻量后端**（`force_http=True`，N 组合 × M 页，浏览器限速跑不完）。

### 1.4 历史回补（评估的数据基础）

| 任务 | 入口 | 产出 |
|---|---|---|
| 单组合回补 | `POST /history` | 单组合全史调仓（`portfolio_history`） |
| 批量回补 | `POST /bulk-history` / `python main.py bulk-history` | `data/history_bulk/<zjzh>.json`（roster 内全部组合，默认 since 2025-12-01） |

## 2. 评估链：高手怎么评出分

### 2.1 信号来源（`load_expert_signals`）

- **sim（默认）**：`crawl_trade`（market_type≠live）**∪** `data/history_bulk/*.json`，按 `(日期, 股票, 方向, 价, 时间)` 五元组去重（bulk 记录带完整权重上下文，同键保留 bulk）。
- **live**：`expert_trades` 视图（crawl_trade 的实盘投影）。
- 过滤条件：`stock_code` 非空 **且** `weight_after`（调仓后仓位）非空——没有权重的记录无法回测。

### 2.2 行情与基准

- `_kline_for`：先查「无行情代码」跳过缓存（`data/eval/price_miss.json`，7 天过期；单次缺失过半视为行情源故障不写缓存，防误伤）→ 缺的调 `prices.ensure_prices` 补（akshare 东财主通道，失败切腾讯 gtimg 兜底）→ 从本地 `prices.db` 建 `{code: {date: kline}}` 索引。
- 基准：`index_closes("000300.SH")` 沪深300。

### 2.3 镜像回测（`simulate_expert`，口径与跟随回测单一事实源）

把高手的调仓记录当作「无脑跟单」跑一遍，常量全部从 `follow_backtest.py` 导入（改一处两边跟随）：

| 环节 | 规则 |
|---|---|
| 信号→目标 | 同一高手同一股票同一交易日，取**日终净目标权重**（weight_after 最后一条，后到者覆盖） |
| 执行 | **T+1 开盘价**成交，滑点 ±0.2%；整百股 |
| 费用 | 佣金万 8（最低 5 元）；**卖出加收印花税万 5** |
| 约束 | 开盘涨停拦截（记 `buy_skipped`）；目标权重 <1% 视为清仓/噪音；变动 < max(500 元, 净值 0.2%) 不调仓；现金不足时按可买量下调 |
| 窗口 | 从该高手**首笔信号日**起（之前没单可跟，净值持平无意义） |
| 停牌/缺行情 | 顺延不了就放弃（与原引擎一致） |

每日记净值 → `nav_daily`；每笔成交 → `trades`（含买卖价、费用、已实现盈亏）。

### 2.4 指标（`compute_metrics`）

- **收益类**：总收益率、年化（365 天折算）
- **风险类**：最大回撤、Calmar（年化/回撤）
- **风险调整**：夏普（√252）、索提诺（只用下行偏差）
- **交易类**：胜率、平均盈利/亏损、盈亏比（按卖出笔统计）
- **相对基准**：超额收益（同时段沪深300）、Alpha·Beta（日收益对中证500 回归，含 t 值）

### 2.5 综合评分与样本门槛

- **评分** = 夏普、索提诺、Calmar、胜率四项的**分位秩平均 ×100**（0-100）。
- **样本门槛**：卖出 < 3 笔 或 覆盖 < 20 个交易日 → `sample_ok=False`，不给分、排序沉底——避免用 3 笔交易谈夏普。
- 排序：样本充足者优先 → 评分降序 → 夏普降序，赋 rank。

### 2.6 产出与消费

- `data/eval/latest.json`（Web 页 `GET /evaluation` 直接读）+ `data/eval/expert_eval_<run_id>.json`（历次留档）。
- 明细 `GET /evaluation/detail?expert_id=...`：同口径现算单高手，返回净值序列 + 基准 + 最近 200 笔成交，供抽屉里的 ECharts 曲线。
- 表格行内**一键关注** → 写 `watchlist` → 直接成为「高手跟随策略」v1 镜像策略的可跟名单。

## 3. 当前数据实况与已知边界

- 入库：943 个高手 / 938 条买入（2026-10-16 单日），5 个组合有批量回补全史 → **当前只有这 5 位入榜**（#1 sz286017443_1 评分 85 / 夏普 2.61）。
- 评估依赖本地行情覆盖其交易标的；未覆盖标的按「顺延不了就放弃」处理，meta 里显示 `n_codes / n_codes_with_price`。
- 镜像回测是「无脑跟单」口径（日终权重、T+1 开盘），不含日内择时；它衡量的是**高手自身的盈利质量**，不等于跟随策略实盘表现（后者另有一套 PIT 无前视 + 随机对照的验证，见「高手跟随策略」页）。
- v3_tiers 机器学习引擎未迁移（mirror/signal 策略不受影响）。
